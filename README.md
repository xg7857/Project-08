# 과제 08: 최소 비용 신장 트리 알고리즘 비교

## 1. 실험 환경

- 정점 50개(번호 0~49)의 가중치 무방향 단순 그래프, 가중치는 1~100의 임의의 양의 정수
- 희소 그래프: 간선 100개 / 밀집 그래프: 간선 600개
- 랜덤 신장 트리를 먼저 만들고 나머지 간선을 추가해서 연결 그래프를 보장하고, DFS로 연결 여부를 한 번 더 확인
- 난수 seed 2026, 희소 그래프는 Case 1과 3에서, 밀집 그래프는 Case 2와 4에서 동일한 그래프 사용
- 인접 리스트 + Kruskal, 인접 행렬 + Prim으로 MST 계산
- 실행시간은 한 환경에서 측정한 값이며, 컴퓨터에 따라 달라질 수 있다.

## 2. 측정 기준

| 항목 | 내용 |
|---|---|
| 메모리 (Kruskal) | 인접 리스트(헤드 배열 + 노드 수 × `sizeof(Node)`) + 간선 배열(E × `sizeof(Edge)`) + Union-Find(parent, rank) + MST 결과 배열 |
| 메모리 (Prim) | 인접 행렬(`int[50][50]`) + key, parent, visited 배열 |
| 실행시간 | 그래프 생성 후 MST 계산만 20,000번 반복해서 측정한 평균 (ms). 4가지 경우 모두 같은 방법 사용 |
| Kruskal 시간 포함 범위 | 리스트에서 간선 모으기 + 간선 정렬 + Union-Find 처리 |

1회 실행은 너무 짧아서 측정이 안 되기 때문에 반복 측정 후 평균을 사용했다.

## 3. 측정 결과

| Case | 구성 | MST 간선 수 | MST 비용 | 메모리(Byte) | 실행시간(ms) |
|---|---|---:|---:|---:|---:|
| 1 | 희소 / 인접 리스트 + Kruskal | 49 | 1668 | 5,796 | 0.004987 |
| 2 | 밀집 / 인접 리스트 + Kruskal | 49 | 289 | 27,796 | 0.046501 |
| 3 | 희소 / 인접 행렬 + Prim | 49 | 1668 | 10,600 | 0.011258 |
| 4 | 밀집 / 인접 행렬 + Prim | 49 | 289 | 10,600 | 0.011745 |

같은 그래프에서 Kruskal과 Prim의 MST 비용이 같았다(희소 1668, 밀집 289). MST 간선 수는 모두 정점 수 - 1 = 49개이다.

## 4. 분석

### 4.1 희소 그래프와 밀집 그래프의 성능 차이

- Kruskal은 밀집 그래프에서 간선이 100개에서 600개로 늘어나자 실행시간이 0.0050ms에서 0.0465ms로 약 9배 늘었다. 정렬해야 할 간선이 6배 많아졌기 때문이다.
- Prim은 희소 0.0113ms, 밀집 0.0117ms로 거의 변하지 않았다. 정점 수가 50개로 같으면 간선 수와 관계없이 행렬을 확인하는 횟수가 같기 때문이다.
- MST 비용은 밀집 그래프(289)가 희소 그래프(1668)보다 훨씬 작다. 간선이 많으면 가중치가 작은 간선을 고를 선택지가 늘어나기 때문이다.

### 4.2 인접 리스트와 인접 행렬의 메모리 사용 차이

- 인접 행렬은 간선 수와 관계없이 50×50칸을 잡아서 그래프 표현에 10,000B가 고정으로 든다. Prim 전체 메모리도 10,600B로 두 경우가 같다.
- 인접 리스트는 간선 수에 비례한다. 희소 그래프에서는 노드 200개(약 3.6KB)만 필요해서 Kruskal 전체 메모리가 5,796B로 Prim보다 작았다.
- 밀집 그래프에서는 노드가 1,200개로 늘고 Kruskal이 간선 배열 600개도 따로 저장해야 해서 27,796B가 되어 Prim의 약 2.6배였다.

### 4.3 Kruskal과 Prim의 실행 특성 차이

- Kruskal은 간선 중심 알고리즘이다. 간선을 정렬하는 O(E log E) 비용이 지배적이라 간선 수에 민감하다.
- Prim(행렬 방식)은 정점 중심 알고리즘이다. 가장 가까운 정점을 찾는 과정이 O(V²)이라 정점 수가 같으면 밀도와 무관하게 일정하다.
- 희소 그래프(E = 100)에서는 Kruskal이 더 빨랐고(0.0050ms 대 0.0113ms), 밀집 그래프(E = 600)에서는 Prim이 약 4배 빨랐다(0.0117ms 대 0.0465ms).

### 4.4 그래프 밀도가 성능에 미치는 영향

- 간선 수에 따라 성능이 달라지는 방법은 인접 리스트 + Kruskal이고, 간선 수와 거의 무관한 방법은 인접 행렬 + Prim이다.
- 간선이 적으면 간선만 저장하고 처리하는 Kruskal이 메모리와 시간 모두 유리하고, 간선이 많아지면 정렬 비용과 리스트 메모리가 커져서 행렬 + Prim이 유리하다.

## 5. 한계

- seed 하나로만 측정했고, 다른 seed에서는 수치가 달라질 수 있다.
